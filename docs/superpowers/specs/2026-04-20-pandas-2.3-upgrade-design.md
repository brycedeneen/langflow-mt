# pandas 2.2.3 → 2.3.x upgrade — design

**Date:** 2026-04-20
**Branch:** platform-multi-tenant
**Status:** design approved, awaiting implementation plan

## Goal

Move the project from `pandas==2.2.3` to the latest `pandas 2.3.x`, eliminate all pandas-emitted `DeprecationWarning` / `FutureWarning` in code we own, and leave pandas 3.0 adoption as a follow-up with no new debt blocking it.

## Background

The pandas team explicitly recommends upgrading to 2.3 and resolving all deprecation warnings *before* attempting 3.0, because 3.0 removes functionality that 2.x has been warning about. This spec covers only the 2.3 step; 3.0 is a separate effort.

Current state:

- `src/backend/base/pyproject.toml:49` — `pandas==2.2.3` (exact pin)
- `src/lfx/pyproject.toml:12` — `pandas>=2.0.0,<3.0.0` (range)
- `src/backend/base/pyproject.toml:117` and top-level `pyproject.toml:36` — `pandas-stubs>=2.1.4.231227`
- 46 source/test files import pandas directly
- 10 transitive deps also consume pandas: cleanlab-tlm, datasets, docling, docling-core, fastparquet, ibm-watsonx-ai, openlayer, pymilvus, vlmrun, yfinance

## Scope decisions

| Decision | Chosen |
|---|---|
| Target version | pandas 2.3.x only; 3.0 is out of scope |
| Warning strictness | Strict — treat pandas `DeprecationWarning`/`FutureWarning` as test errors during this work |
| Test gate | Hybrid — pandas-touching files as inner loop; full backend+lfx unit suites as final gate |
| Pin style | Range `>=2.3,<3.0` in both backend and lfx (align the two packages) |
| Transitive conflicts | If `uv lock` blocks, stop and report — do not expand scope to upgrade other deps |
| Approach | Hybrid: proactive grep-based audit for ~5 high-signal patterns, then runtime-driven fix loop |

## Out of scope

- pandas 3.0 adoption
- Starter project JSON fixtures (flow definitions, not Python code)
- Transitive-dep upgrades (pymilvus, docling, etc.)
- Unrelated deprecations from langchain or other libraries
- Style/performance refactors of pandas code

## Phase 1 — proactive audit

Before bumping the pin, grep the 46 pandas-touching files for a fixed list of high-signal deprecations. The list is not expanded mid-session; anything not on this list falls to Phase 2.

Target patterns:

1. **`df.append(...)`** — removed in 2.0. Replace with `pd.concat`.
2. **`DataFrame.applymap` / `Series.applymap`** — deprecated in 2.1. Replace with `DataFrame.map`.
3. **`inplace=True`** on chained method calls (e.g., `df.foo(...).bar(inplace=True)`) — Copy-on-Write makes these no-op silently in 3.0. Rewrite as assignment. (We do NOT grep for all `inplace=True` — too noisy; only chained cases or ones the test suite surfaces.)
4. **`errors='ignore'`** in `to_numeric` / `to_datetime` / `to_timedelta` — deprecated in 2.2. Replace with explicit try/except or strategy change.
5. **Positional arguments to keyword-only methods** (e.g., `df.reset_index(False)`). Convert to keyword arguments.
6. **`squeeze=` argument** in `pd.read_csv` and related I/O. Use `.squeeze()` post-call.
7. **Chained assignment producing `SettingWithCopyWarning`** — any existing suppressions should be rewritten; 3.0 Copy-on-Write turns these into silent bugs.

Rules:

- One grep per pattern across `src/backend/` and `src/lfx/`, excluding `.json`, `__pycache__`, `.venv`, `.worktrees`.
- Each match is either fixed or explicitly triaged as a false positive (e.g., `.append()` on a list).
- No unrelated refactors.

## Phase 2 — runtime-driven fix loop

### Setup

1. Apply pin changes.
2. `uv lock` — if it conflicts, stop and report per the transitive-dep policy.
3. `uv sync`.
4. Confirm `pandas.__version__` is `2.3.x`.

### Warnings-as-errors configuration

Scoped to pandas so third-party warnings stay informational. Applied via pytest CLI flags on the fix loop only — `pyproject.toml` pytest config is not modified.

```
-W error::DeprecationWarning:pandas
-W error::FutureWarning:pandas
-W error::DeprecationWarning:pandas.*
-W error::FutureWarning:pandas.*
```

### Inner-loop test file set

Run these under the strict flags:

**Backend (`src/backend/tests/unit/`):**
- `serialization/test_serialization.py`
- `test_knowledge_bases_api.py`
- `components/bundles/google/test_google_bq_sql_executor_component.py`
- `components/search/test_google_search_api.py`
- `components/processing/test_type_converter_component.py`
- `components/processing/test_dataframe_operations.py`
- `components/processing/test_parse_dataframe_component.py`
- `components/data_source/test_web_search.py`

**lfx (`src/lfx/tests/unit/`):**
- `components/sftp/test_sftp_csv_upload.py`
- `schema/test_schema_dataframe.py`
- `schema/test_schema_data_set.py`

lfx tests require `LFX_TEST_ALLOW_LANGFLOW=1` when run from the repo-level venv.

### Fix-loop rules

- Minimal, targeted fixes; no surrounding cleanup.
- Real behavior changes — tests that fail because pandas 2.3 changed actual return values, dtypes, or semantics (not just emitted a warning) — get fixed but explicitly flagged in the final report so the user can review the absorbed change.
- Warnings emitted by third-party libraries we do not own (e.g., pandas warnings triggered inside `datasets` or `docling`) are recorded and skipped — we do not modify upstream packages.

### Exit condition

Every file in the inner-loop set passes under the strict flags.

## Phase 3 — full-suite gate

- `uv run pytest src/backend/tests/unit` under the strict pandas flags.
- `LFX_TEST_ALLOW_LANGFLOW=1 uv run pytest src/lfx/tests/unit` under the strict pandas flags.
- New pandas warnings surfaced outside the original 46 files get fixed in place and re-run.
- Third-party-emitted warnings get explicitly un-stricted via `-W "default::DeprecationWarning:<module>"` so they no longer fail the gate. Anything still erroring is ours.
- Integration suite is not part of this gate.

Exit condition: both unit suites pass under the strict flags, with any third-party exceptions documented.

## Rollback

All work stays on `platform-multi-tenant` with no upstream pushes. If unrecoverable, `git restore` reverts pyproject/lock changes. Per user policy, no commits happen without explicit permission, so rollback surface is small.

## Deliverables

1. Edited `pyproject.toml` files (2 × pandas pin, 2 × pandas-stubs).
2. Regenerated `uv.lock`.
3. Code changes across the 46 files from Phase 1 and Phase 2.
4. Written summary: patterns fixed, third-party warnings deferred (with module names), any real-behavior changes absorbed.
5. No commits unless explicitly requested.
