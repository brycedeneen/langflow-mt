## Stopgap: pandas override for `ibm-watsonx-ai`

`uv lock` initially failed: every `ibm-watsonx-ai` version (1.3.1 through 1.5.x) pins `pandas>=0.24.2,<2.3.0`. No released version supports pandas 2.3.

**Resolution chosen:** added `pandas>=2.3,<3.0` to `tool.uv.override-dependencies` in the top-level `pyproject.toml`. This tells uv to ignore ibm-watsonx-ai's upper bound and resolve pandas to 2.3.

**Risk:** resolver lie — ibm-watsonx-ai *may* break at runtime on pandas 2.3 despite its pin. The watsonx test files pass under strict pandas flags, which reduces but doesn't eliminate the risk.

**Follow-up captured in project memory** (`project_remove_watsonx.md`, indexed in `MEMORY.md`): the deploy target does not include IBM watsonx; full removal (~50+ files: `lfx/components/ibm/` dir, `lfx/base/models/` watsonx entries, frontend provider config, 30+ starter project JSON references, tests) will eliminate both the stopgap and shrink the deploy surface.

## Third-party warnings we accept

Two deprecation warnings surface during test runs. Neither is pandas-related; both come from upstream libraries we pin:

1. **`langchain_google_genai/chat_models.py:47`** — `FutureWarning` about the deprecated `google.generativeai` package. Source: langchain-google-genai 2.0.6 (we pin exact). Latest on PyPI is 4.2.2, which has migrated to `google.genai`. Bumping is coupled with the parked langchain 0.3 → 1.x migration.

2. **`altk/pre_tool/core/config.py:31`** — `PydanticDeprecatedSince20` (class-based `Config`). Source: `agent-lifecycle-toolkit~=0.4.4` (the `[altk]` backend extra). Will break on Pydantic v3 removal; upstream fix required. Relevant to a future Pydantic v3 migration, not this upgrade.

Neither requires action here.
