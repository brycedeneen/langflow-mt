## Unexpected scope expansion: Python floor bump

The spec anticipated resolver-lie blockers but not that pandas 3.0 itself requires Python ≥ 3.11. When the Phase 2 pin bump was applied and `uv lock` ran, the error was:

```
Because the requested Python version (>=3.10, <3.14) does not satisfy
Python>=3.11 and pandas>=3.0.0 depends on Python>=3.11, we can conclude
that pandas>=3.0.0 cannot be used.
```

The spec's abort condition fired; user was consulted with three options (raise Python floor, abort, or reframe as a 2.3-only win). User picked option A — raise `requires-python` from `>=3.10` to `>=3.11` across all three pyprojects. Justification: Python 3.10 is six months from EOL (2026-10-31), in security-only mode, and is increasingly the first version dropped by maintained libraries. Dropping it now avoided another parked migration.

This change was bundled into the Phase 2 commit with an adjusted message calling it out.

## Phase 1 — CoW pre-flush (pandas 2.3.3)

**Setup.** Added a module-level opt-in to both test trees' conftest files:

```python
import pandas as _pd_cow  # noqa: E402
_pd_cow.options.mode.copy_on_write = True
```

Placement at conftest import time (not inside a fixture) is load-bearing — the option must be active before test-imported modules run any pandas code. Guard tests (`test_pandas_cow_enabled.py` in each tree) assert the setting is live.

**Results.** 246 inner-loop tests + 7263 full-suite tests passed under strict flags with CoW active. Zero chained-mutation or CoW warnings surfaced in our code. Phase 1 needed **zero source fixes**.

| lfx non-CLI unit | 1585 | 19 | 0 | 8 |

All 73 + 19 = 92 failures + 7 errors were pre-existing branch drift in the multi-tenant WIP clusters from the 2.3 report (`test_webhook`, `test_user`, `test_session_endpoint`, `test_dynamic_imports`, `test_flow`, `test_memory`, etc.) plus a small number of newer test files added since the 2.3 work (`test_assistant_mutation`, `test_flow_folder_integrity`, `test_mcp_servers_file`, `test_tracing/test_repository`) — none pandas-related.

## Phase 2 — pin bump + overrides + smoke probes

**`uv lock` outcome.**

First attempt (just pandas pins bumped): failed on `pandas>=3.0` requiring Python ≥ 3.11 (see "Unexpected scope expansion" above). After bumping `requires-python` to `>=3.11`, the lock resolved cleanly in 2.14s — no other transitive caps surfaced.

**Smoke probes added.** Five new files under `src/backend/tests/unit/integration_smoke/`:

- `__init__.py`
- `conftest.py` (registers `@pytest.mark.smoke`)
- `test_pandas_3_overrides_watsonx.py` (2 probes)
- `test_pandas_3_overrides_docling.py` (2 probes)
- `test_pandas_3_overrides_cleanlab.py` (2 probes)

**Results.** 6/6 probes pass on pandas 3.0.2. All three deps import cleanly and exercise first-call pandas surfaces without `ImportError` / `AttributeError`. Resolver-lies are not lies.

One minor spec bug was caught and fixed inline during probe development: the cleanlab probe originally asserted `cleanlab_tlm.__version__`, but that package does not expose a module-level `__version__`. The probe was rewritten to use `importlib.metadata.version("cleanlab-tlm")`. This check is identical on pandas 2 or 3 and never reflected a real override issue.
