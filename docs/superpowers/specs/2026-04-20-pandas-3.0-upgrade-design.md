# pandas 2.3.3 → 3.0.x upgrade — design

## Goal

Move the workspace from `pandas==2.3.3` to the latest `pandas 3.0.x`, absorb the Copy-on-Write and PyArrow-backed-string-dtype semantic shifts, and finish with zero pandas `DeprecationWarning` / `FutureWarning` across backend + lfx unit suites.

## Background

The 2.3 upgrade (`2026-04-20-pandas-2.3-upgrade-report.md`) landed cleanly — no code changes needed, ~7200 tests pass strict pandas flags. 3.0 went GA on 2026-01-21; 3.0.2 shipped 2026-03-30.

Three pandas behavior changes in 3.0 that 2.3 strict-warning gates did not catch:

- **Copy-on-Write (CoW) is default and only** — chained-indexing mutations silently no-op.
- **PyArrow-backed string dtype default** — different identity, equality, `.dtype` reprs. PyArrow 19 is already in the lockfile.
- **Removed APIs** — anything deprecated in 2.x and still called in a cold path is now an error at call time, not a warning at import time.

Three transitive deps explicitly cap `pandas<3.0`:

| Dep | Cap declared | Currently pinned |
|---|---|---|
| `cleanlab-tlm` | `pandas==2.*` | 1.1.39 |
| `docling` | `pandas<3.0.0,>=2.1.4` | 2.70.0 |
| `ibm-watsonx-ai` | `pandas<2.4.0,>=0.24.2` | 1.5.6 |

watsonx is already resolver-overridden from the 2.3 work. docling has a parked follow-up spec (`2026-04-20-docling-ecosystem-bump-design.md`) covering its full bump. cleanlab-tlm has no upstream pandas-3-compatible release at the time of this spec.

## Scope decisions

| Decision | Chosen |
|---|---|
| Target version | pandas 3.0.x (`>=3.0,<4.0`) |
| Dep-blocker policy | `tool.uv.override-dependencies` for all three caps, plus targeted runtime smoke probes |
| Phasing | Three phases: CoW pre-flush on 2.3 → pin bump + smoke → full strict run on 3.0 |
| Pin style | Range `>=3.0,<4.0` in backend base and lfx (aligned) |
| Warning strictness | Strict — pandas-emitted `DeprecationWarning` / `FutureWarning` as test errors |
| Test gate | Hybrid — inner loop from 2.3 spec + full backend + lfx non-CLI unit suites |
| Commit cadence | One commit per phase; pause-before-commit per user policy |

## Out of scope

- Watsonx removal (captured in project memory; standalone effort).
- Docling ecosystem bump (parked spec).
- Transitive-dep upgrades other than the three pandas-blocker overrides.
- Starter project JSON fixtures.
- New pandas-3 idioms (`pd.col()`, explicit string-dtype migration) — behavior changes only.
- Unrelated deprecations from langchain, pydantic, altk, etc.
- pandas-stubs mypy fallout (no mypy gate; stub drift tracked separately).
- Integration suite; lfx `cli/` subsuite (pre-existing failures per 2.3 report).

## Phase 1 — CoW pre-flush on pandas 2.3.3

**Setup.** Add a top-level statement (not a fixture) in both `src/backend/tests/conftest.py` and `src/lfx/tests/conftest.py`:

```python
import pandas as pd
pd.options.mode.copy_on_write = True
```

Module-level in conftest, **not** a session fixture — the option must be active before test-imported modules run any pandas code, and conftest evaluates before test module import. A fixture (even autouse session-scoped) runs too late for pandas state that was captured at test-module import time.

String dtype opt-in (`pd.options.future.infer_string = True`) is **not** turned on in Phase 1 — that churn is absorbed in Phase 3 where its strict-run debug cost lives natively, not speculatively on 2.3.

**Execution.**

1. Inner loop (11 files, same set as 2.3 report) under strict flags:
   - `-W error::DeprecationWarning:pandas`
   - `-W error::FutureWarning:pandas`
   - `-W error::DeprecationWarning:pandas.*`
   - `-W error::FutureWarning:pandas.*`
2. Full backend + lfx non-CLI unit suites under the same flags.
3. Fix every pandas-emitted `ChainedAssignmentError` / CoW warning in our code. Rewrite chained mutations as explicit assignment per pandas 3.0 guidance.
4. Third-party CoW warnings get un-stricted via `-W "default::...:<module>"` and logged.

**Inner loop file set** (carried forward from 2.3 spec):

Backend (`src/backend/tests/unit/`):
- `serialization/test_serialization.py`
- `test_knowledge_bases_api.py`
- `components/bundles/google/test_google_bq_sql_executor_component.py`
- `components/search/test_google_search_api.py`
- `components/processing/test_type_converter_component.py`
- `components/processing/test_dataframe_operations.py`
- `components/processing/test_parse_dataframe_component.py`
- `components/data_source/test_web_search.py`

lfx (`src/lfx/tests/unit/`, requires `LFX_TEST_ALLOW_LANGFLOW=1`):
- `components/sftp/test_sftp_csv_upload.py`
- `schema/test_schema_dataframe.py`
- `schema/test_schema_data_set.py`

**Exit condition.** Both suites clean of pandas-emitted CoW warnings. Any real behavior changes (not just warning noise) get flagged in the report.

**Commit.** `chore(pandas): enable Copy-on-Write opt-in on pandas 2.3` — conftest fixture + any chained-mutation fixes.

## Phase 2 — pin bump + override update + dep smoke

**Setup.**

1. Apply all pin changes from the Pin Changes table.
2. Rewrite the `tool.uv.override-dependencies` pandas entry with the updated comment.
3. `uv lock`. If it fails for any reason other than the three known caps (e.g., a fourth pandas cap surfaces from an unlisted transitive), **abort and report** — do not expand scope to upgrade other deps.
4. `uv sync`.
5. Confirm `pandas.__version__` is 3.0.x.

**Smoke probes.** New file `src/backend/tests/unit/integration_smoke/test_pandas_3_overrides.py` — marker `@pytest.mark.smoke`, collected in default unit run, skipped if the relevant dep extra isn't installed. Each probe is small (~10 lines) and hits the dep's pandas surface without any network or auth.

- **watsonx probe** — import `APIClient` and any pandas-touching helper; instantiate minimally. Assert imports resolve and pandas-consuming internals exist.
- **docling probe** — import `DocumentConverter`; call a path that touches its pandas internals on an empty input (`convert_all([])` or equivalent). Or construct `DoclingDocument` and call a `to_*` method known to traverse pandas.
- **cleanlab-tlm probe** — import `TLM` and whatever pandas-consuming helper exists (`cleanlab_tlm.utils` surface). If no pandas code runs without a live API key, fall back to `import cleanlab_tlm` + attribute-existence asserts on pandas-consuming paths.

**Rules.**

- Network / auth errors → skip with message (we do not hit these services).
- `ImportError` / `AttributeError` / `TypeError` → fail — the override is a lie and something must be fixed before this upgrade ships.
- Probes stay in-tree post-upgrade; they guard overrides on future pandas bumps.

**Exit condition.** `uv sync` succeeds; three smoke probes pass (no strict flags in Phase 2 smoke — imports/first-calls should just work; strict is Phase 3).

**Commit.** `build(deps): bump pandas 2.3 -> 3.0, refresh override list, add dep smoke probes`.

## Phase 3 — full strict-warnings runtime loop on pandas 3.0

**Execution.**

1. Inner loop under strict flags + CoW conftest opt-in (kept in place — CoW is now the pandas default on 3.0, but keeping the opt-in asserts intent and survives later dep-upgrade churn).
2. Full backend + lfx non-CLI unit suites under strict flags.
3. Smoke probes re-run under strict flags.
4. Fix pandas-touching code that surfaces breakage:
   - PyArrow-string-dtype assertions: `.dtype == "object"` → `"string"` or `"str"` per pandas 3 defaults.
   - NaN equality: PyArrow strings use proper NA semantics; `== np.nan` / `is np.nan` checks need `pd.isna`.
   - Removed API call sites not caught at import (any `.append()`, `.applymap()`, `errors='ignore'` matches that sat in cold paths in the 2.3 audit).
5. Third-party warnings outside our call sites get un-stricted and recorded in the final report.

**Exit condition.** Inner loop + both unit suites clean of pandas warnings on pandas 3.0.0+; delta against the 2.3-baseline failure list is zero (or explicitly attributed to pandas 3 and fixed).

**Commit.** `fix(pandas): absorb pandas 3.0 behavior changes (CoW, PyArrow strings, removed APIs)`.

## Test gates — summary

| Phase | Gate |
|---|---|
| 1 | Inner loop + full backend + lfx non-CLI unit suites under strict pandas flags, with CoW fixture active. Clean of pandas warnings. |
| 2 | `uv lock` + `uv sync` succeed; `pandas.__version__` == 3.0.x; three smoke probes pass. |
| 3 | Inner loop + full backend + lfx non-CLI unit suites + smoke probes under strict pandas flags on pandas 3.0. Clean of pandas warnings; zero baseline delta. |

Third-party-emitted warnings get un-stricted per 2.3 pattern and logged per-module in the final report.

Any delta beyond this baseline at Phase 3 exit is pandas-3-induced and must be addressed.

## Risks

- **Resolver-lie runtime blowup.** docling or cleanlab-tlm may actually break on pandas 3.0 despite the override. Smoke probes are the canary; if they fail, abort Phase 2 and report — do not patch upstream packages.
- **CoW pre-flush surfaces wide breakage.** If Phase 1 uncovers more than a handful of chained-mutation bugs, scope has ballooned. Stop and re-brainstorm rather than grinding through — "too big" is a signal.
- **PyArrow-string-dtype test churn.** Many tests likely assert `.dtype == "object"` or compare NaN with `==`. Phase 3 is budgeted for this; real behavior changes flagged in the report.
- **Uncaught fourth blocker.** `uv lock` could reveal a pandas cap from an unlisted transitive dep. Abort condition stands — stop and report per 2.3 precedent.

## Rollback

All work stays on `platform-multi-tenant`, no upstream push (per user policy: no PRs to langflow-ai/langflow). One commit per phase keeps each phase `git revert`-able in isolation. Phase 2 revert lands us back on 2.3.3 + the Phase 1 CoW opt-in (still a net improvement even if 3.0 is unreachable).

## Deliverables

1. Phase 1 commit: conftest CoW fixture (backend + lfx) + any chained-mutation fixes.
2. Phase 2 commit: pin/override/lockfile updates + three smoke probes.
3. Phase 3 commit: pandas-3 behavior-change fixes.
4. Final report at `docs/superpowers/specs/2026-04-20-pandas-3.0-upgrade-report.md` — mirrors 2.3 report structure: patterns fixed, third-party warnings deferred (with module names), absorbed behavior changes flagged for user review.
5. This spec doc.

Per project policy, no commits happen without explicit user permission.
