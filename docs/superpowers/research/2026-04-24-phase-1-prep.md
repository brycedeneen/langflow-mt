The command **works as written**. Phase 1.1's Makefile target ships unchanged.

### Two warnings worth flagging

1. **Six duplicate-operation-ID warnings** in MCP streamable-http routes (`mcp.py`, `mcp_projects.py`):

   ```
   Duplicate Operation ID handle_streamable_http_api_v1_mcp_streamable__get
   Duplicate Operation ID handle_streamable_http_api_v1_mcp_streamable_get
   Duplicate Operation ID handle_project_streamable_http_api_v1_mcp_project__project_id__streamable__get
   Duplicate Operation ID handle_project_streamable_http_api_v1_mcp_project__project_id__streamable_get
   Duplicate Operation ID handle_streamable_http_api_mcp_streamable__get
   Duplicate Operation ID handle_streamable_http_api_mcp_streamable_get
   ```

   These are real backend bugs — the same handler is registered twice with slightly different paths (trailing slash variants). `openapi-zod-client` may emit duplicate schema constants. Mitigations:

   - **Best:** fix in backend (rename one path of each pair, or unify into one route with a redirect). ~30 min of backend work, separate from this project.
   - **Acceptable:** post-process in `scripts/gen-schemas.mjs` to dedupe schema names. ~15 min, lives in this project.
   - **Recommendation:** do the post-process dedupe in this project so Phase 1 isn't gated on a backend cleanup; open a separate ticket for the backend fix.

2. **Pydantic field-name shadowing** in `lfx/components/processing/_data_mapper/config_schema.py:38` (`InputDef.schema` shadows BaseModel attribute). Pre-existing, unrelated, doesn't affect schema generation.

## Q2 — Phase 1.3 hand-written schema scope (the OpenAPI-hidden routers)

### Original plan estimate

9 schema files for ~34 hidden endpoints, ~1 week of work bundled into Chunk 1.

### Reality after audit

**14 router-equivalents to schema, ~50–60 individual routes total**, every one of them consumed by the frontend.

#### Fully-hidden routers (router-level `include_in_schema=False`)

| Router | Routes | Frontend hooks today | Schema effort |
|---|---|---|---|
| `/store/*` (Components Store) | 9 | 3 (tags, likes, check) | 60 min |
| `/voice/*` | 1 (`elevenlabs/voice_ids`) | 1 | 5 min |
| `/models/*` | 10 (providers, defaults, validation, enabled lists) | 5 | 90 min |
| `/model_options/*` | 2 (language, embedding) | likely 1–2 | 10 min |
| `/folders/*` | ~10 (full CRUD + uploads + downloads) | 8 | 60 min |
| `/knowledge_bases/*` | ~10 (CRUD + ingestion + chunks) | 6 | 60 min |
| `/registration/*` (v2) | 2 (get, post) | 2 | 15 min |

**Subtotal: 7 routers, ~44 routes, ~5 hours.**

#### Hidden routes inside otherwise-public routers

| Router | Hidden routes | Frontend usage | Schema effort |
|---|---|---|---|
| `api_key.py` | 4 (GET, POST, DELETE, POST /store) | 3 hooks | 20 min |
| `login.py` | 4 (login, refresh, session, logout) | 4 hooks | 45 min |
| `variable.py` | 4 (full CRUD) | 5 hooks | 30 min |
| `validate.py` | 2 (`/code`, `/prompt`) | inline call sites | 10 min |
| `chat.py` | 3 (all `deprecated=True` `/build/*` legacy) | **zero — no frontend usage** | skip |
| `endpoints.py` | 5 (run/session, webhook-events, deprecated task, custom_component x2) | partial — only custom_component | 30 min |
| `flows.py` | 2 (PUT /{id}, POST /expand/) | possibly 1–2 | 15 min |

**Subtotal: 7 routers, ~24 routes (minus 3 deprecated chat = 21), ~3 hours.**

#### Grand total

- **14 schema files** (one per router), not 9 as the plan said
- **~65 routes** to schema (50 active + 15 internal we'd schema for completeness)
- **~7–8 hours of focused authoring**, not the ~1 day the plan implied

The plan's Phase 1 estimate of "~1 week" still holds, but Phase 1.3 alone now occupies ~1 day of that, with Phase 1.1 (Makefile + openapi extraction) and Phase 1.2 (gen-schemas.mjs post-processor) consuming the rest.

### Scope-reduction options if 7–8 hours is too much for one push

1. **Skip deprecated routes.** `chat.py`'s 3 `/build/*` legacy routes have zero frontend usage — schema as `z.unknown()` placeholder, log a backend cleanup ticket. (Already factored above.)
2. **Defer rarely-touched domains.** `/store/*` (3 hooks), `/voice/*` (1 hook) account for ~65 min and are read-only smoke surfaces. Could be Phase 2.h follow-on rather than Phase 1.
3. **Phase 1 scopes down to "auth + variables + api_key + validate + flows-internal" (~2 hours)** — the things the frontend uses on every page-load. Models, folders, knowledge_bases, store, voice, registration all defer to a Phase 1.5.

### Recommendation

Author all 14 routers in one Phase 1.3 push. Reasons:

- One sweep through the backend is more efficient than three. Most of the time is reading Pydantic models — once your head is in that file, knocking out the schemas next door is cheap.
- The CI guard (Python lint that fails when a new `include_in_schema=False` route lacks a schema) needs the full set to be useful. A partial set means the CI guard fires for legitimate work.
- The schemas don't need to be polished. Permissive zod schemas (`z.object({...}).passthrough()`) are fine for Phase 1 — they validate the few fields we know are required and pass-through the rest. Phase 2.* tightens per-endpoint when call sites migrate.

If the 7–8 hour estimate gives pause, the right move is to budget Phase 1 as 2–3 working sessions instead of one — not to scope-cut the schema set.

   ```js

   const seenSchemaNames = new Set();
   for (const file of generatedFiles) {
     for (const declName of file.declarations) {
       if (seenSchemaNames.has(declName)) {
         console.warn(`Skipping duplicate schema ${declName} in ${file.tag}`);
         file.declarations.delete(declName);  // keep first occurrence only
       } else {
         seenSchemaNames.add(declName);
       }
     }
   }
   ```
